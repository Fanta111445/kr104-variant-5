Что требуется по заданию

Сравнить вход только по паролю и вход по паролю с одноразовым кодом. Для каждого способа отдельно проверить постороннего и владельца учётной записи.

  • Посторонний знает пароль с вероятностью 1%, 5% или 10%. Если пароль ему неизвестен, вход завершается отказом. При известном пароле второй этап он проходит с вероятностью 0,1%.
  • Владелец всегда знает пароль. На втором этапе он может получить отказ с вероятностью 0%, 10% или 20%.
  • Для каждой из девяти пар параметров выполнить по 1 000 000 независимых попыток на каждого участника и способ защиты. У одной попытки один исход. Повторных вводов нет.
  • Подготовить программу, таблицу девяти результатов, две диаграммы и объяснение различий. Проверить все четыре сочетания знания пароля и правильности кода.

Два участника и два способа дают четыре группы. Поэтому общий объём равен 9 × 1 000 000 × 4 = 36 000 000 попыток.

Источник условия — КР104.pdf, страница 5. Здесь «удобство» измеряется долей успешных попыток владельца.

Почему код повышает безопасность

Обозначим вероятность знания пароля через p, вероятность отказа владельцу через q. Вероятность угадывания кода при известном пароле равна r = 0,001. Это число соответствует 0,1%.

УчастникТолько парольПароль и код
Постороннийpp × 0,001
Владелец11 − q

При p = 0,05 шанс чужого входа по паролю равен 5%. С дополнительным кодом он равен 0,05 × 0,001 = 0,00005, то есть 0,005%. На миллион попыток ожидается около 50 таких входов.

Теоретически дополнительный код уменьшает риск в 1000 раз. При этом 10% отказов на втором этапе уменьшают долю успешных входов владельца до 90%. При безотказном получении кода владелец сохраняет 100% успехов.

Для редкого события счётчик заметно колеблется. В нашем прогоне при 5% компрометации и 10% отказов получилось 43 чужих входа с кодом. Математическое ожидание для этой группы равно 50.

Правило входа · строки 7–15

bool canLogIn(bool password_known, bool needs_code, bool code_correct) {
    if (!password_known) {
        return false;
    }
    if (needs_code) {
        return code_correct;
    }
    return true;
}

bool хранит true или false. Параметры функции означают «пароль известен», «требуется код», «код верен». Если пароль неизвестен, return false сразу завершает функцию. При включённом втором этапе возвращается результат проверки кода. Если пароль известен и код не требуется, возвращается true.

Например, canLogIn(true, false, false) даёт успех. А canLogIn(false, true, true) даёт отказ уже на первой проверке.

Проверка одного случая · строки 17–26

bool checkCase(bool password_known, bool code_correct,
               bool expected_password, bool expected_two_step) {
    const bool password = canLogIn(password_known, false, code_correct);
    const bool two_step = canLogIn(password_known, true, code_correct);
    const bool passed = password == expected_password && two_step == expected_two_step;
    std::cout << "password=" << password_known << " code=" << code_correct
              << " | password_only=" << password << " two_step=" << two_step
              << " | " << (passed ? "PASS" : "FAIL") << '\n';
    return passed;
}

checkCase вызывает правило входа для двух способов защиты. Затем сравнивает оба ответа с ожидаемыми. Переменная passed равна true, если совпали оба результата.

Выражение passed ? "PASS" : "FAIL" выбирает текст. При верном условии берётся значение перед двоеточием, при неверном — после него. В консоли bool выводится как 1 или 0.

Начало программы и режим проверки · строки 28–41

int main(int argc, char* argv[]) {
    if (argc == 2 && std::string(argv[1]) == "--test") {
        const bool test1 = checkCase(false, false, false, false);
        const bool test2 = checkCase(false, true, false, false);
        const bool test3 = checkCase(true, false, true, false);
        const bool test4 = checkCase(true, true, true, true);
        return (test1 && test2 && test3 && test4) ? 0 : 1;
    }

    const bool save_csv = argc == 3 && std::string(argv[1]) == "--csv";
    if (argc != 1 && !save_csv) {
        std::cerr << "Usage: kr104 [--test | --csv PATH]\n";
        return 2;
    }

argc — количество аргументов вместе с именем программы. argv — массив указателей на текст этих аргументов. В команде kr104.exe --csv my-results.csv значение argc равно 3, argv[1] содержит --csv, а argv[2] — имя файла.

При --test выполняются четыре случая из задания. Возврат 0 означает, что все проверки прошли, 1 — что хотя бы одна не прошла. Обычная симуляция после этого не запускается.

save_csv становится истинным при правильной команде с --csv. Для остальных неизвестных вариантов программа выводит подсказку и завершается с кодом 2. В выражениях с && C++ проверяет правую часть только при истинной левой. Так проверка argc защищает обращение к отсутствующему аргументу.

Параметры эксперимента · строки 57–62

    const int attempts = 1'000'000;
    const int seed = 104005;
    const int password_chances[] = {1, 5, 10};
    const int owner_failures[] = {0, 10, 20};
    std::mt19937 generator(seed);
    std::uniform_int_distribution<int> random_number(1, 1000);

const запрещает менять значение после объявления. Апострофы в 1'000'000 только помогают прочитать число. Обычные массивы содержат три значения каждого параметра в процентах.

std::mt19937 создаёт последовательность псевдослучайных чисел. Число 104005 — начальное значение, или seed. uniform_int_distribution<int> выбирает целое от 1 до 1000 включительно. Каждый вызов random_number(generator) использует следующий результат генератора.

Готовая программа с фиксированным seed воспроизводит этот CSV при повторном запуске. При сборке с другой стандартной библиотекой отдельные случайные счётчики могут отличаться.

Девять сочетаний и миллион проходов · строки 71–98

    for (int password_chance : password_chances) {
        for (int owner_failure : owner_failures) {
            int outsider_password = 0;
            int outsider_two_step = 0;
            int owner_password = 0;
            int owner_two_step = 0;

            for (int attempt = 0; attempt < attempts; ++attempt) {
                // 10 outcomes out of 1000 correspond to 1 percent.
                const bool knows_password_only = random_number(generator) <= password_chance * 10;
                const bool knows_password_two_step = random_number(generator) <= password_chance * 10;
                // Only one outcome out of 1000 is a correct guess.
                const bool guesses_code = knows_password_two_step && random_number(generator) == 1;
                const bool receives_code = random_number(generator) > owner_failure * 10;

                if (canLogIn(knows_password_only, false, false)) {
                    ++outsider_password;
                }
                if (canLogIn(knows_password_two_step, true, guesses_code)) {
                    ++outsider_two_step;
                }
                if (canLogIn(true, false, false)) {
                    ++owner_password;
                }
                if (canLogIn(true, true, receives_code)) {
                    ++owner_two_step;
                }
            }

Первый for по очереди берёт 1, 5 и 10 из массива вероятностей компрометации. Для каждого значения второй for перебирает 0, 10 и 20 процентов отказа владельцу. Получается 3 × 3 = 9 сочетаний.

В начале каждого сочетания четыре счётчика обнуляются. Третий цикл начинается с attempt = 0, выполняется, пока attempt < attempts, и после каждого прохода увеличивает attempt на единицу. Это даёт миллион проходов.

Для двух способов входа постороннего берутся разные случайные числа. При вероятности 5% пароль известен, когда выпадает число не больше 5 × 10 = 50. Для кода нужен исход 1 из тысячи. Если пароль неизвестен, правая часть && с проверкой кода пропускается.

У владельца второй этап успешен, если число больше owner_failure × 10. При 10% отказов числа 1–100 дают отказ, 101–1000 — успех. При 0% отказов подходят все значения от 1 до 1000.

СчётчикЧто считает
outsider_passwordУспешные входы постороннего по паролю.
outsider_two_stepУспешные входы постороннего по паролю и коду.
owner_passwordВходы владельца по паролю. Каждый раз успешны.
owner_two_stepВходы владельца с успешным вторым этапом.

Каждый if вызывает canLogIn. При успехе ++ прибавляет к нужному счётчику единицу. Владелец всегда знает пароль, поэтому в его вызовах первым аргументом стоит true.

Для каждого счётчика применяется формула 100.0 × успехи / попытки. Запись 100.0 делает вычисление вещественным и сохраняет дробную часть. double хранит результат с дробной частью.

setw(10) задаёт минимальную ширину следующего выводимого значения. Число 10 определяет выравнивание, а точность по-прежнему задаёт setprecision(4).

Разберём один проход цикла

Пусть вероятность знания пароля равна 5%, а отказа владельцу — 10%. Рассмотрим заранее выбранные числа

  1. Постороннему для входа по паролю выпало 30. Это не больше 50, поэтому он входит, и outsider_password увеличивается.
  2. Для отдельной попытки с кодом ему выпали 41 на проверке пароля и 278 на проверке кода. Пароль известен, код не угадан. Счётчик outsider_two_step не увеличивается.
  3. Владелец входит по паролю, поэтому owner_password увеличивается.
  4. Для второго этапа владельца выпало 87. Это попадает в первые 100 значений, соответствующие отказу. Счётчик owner_two_step не увеличивается.

Сопоставь теорию и эксперимент

Риск чужого входа растёт с вероятностью компрометации пароля. Параметр отказа владельца по модели не влияет на постороннего, поэтому различия между его результатами при одинаковом p возникают из-за случайности.

При 0% отказов код сохраняет владельцу 100% успешных попыток. При 10% и 20% отказов остаётся около 90% и 80%. В этой модели лучший баланс даёт второй этап с надёжным получением кода.

Как объяснить на защите

Я сравниваю вход по одному паролю и вход с дополнительным кодом. Два внешних цикла перебирают девять сочетаний вероятностей. Внутренний цикл оценивает по миллиону попыток на каждого участника и способ. Случайное число от 1 до 1000 моделирует события. Для вероятности 5% подходят первые 50 чисел, а для угадывания кода подходит только 1. Функция canLogIn проверяет пароль и при необходимости код. Успехи считаются отдельно и переводятся в проценты.
Почему девять строк, а попыток 36 миллионов?

Три значения вероятности компрометации умножаются на три значения отказа, получается девять сочетаний. У каждого сочетания четыре группы по миллиону попыток, поэтому 9 × 4 × 1 000 000 = 36 000 000.

Зачем владельцу проверять пароль, если он всегда его знает?

Одна функция описывает общее правило доступа. Владелец передаёт ей true в качестве первого аргумента. Это явно отражает условие задания.

Почему нельзя просто написать random % 1000?

Равномерность остатка зависит от исходного диапазона. В программе стандартное равномерное распределение берёт на себя корректный выбор числа из нужного диапазона.

Почему именно mt19937 и seed 104005?

mt19937 — стандартный генератор для воспроизводимого моделирования. Seed задаёт начальное состояние. Число 104005 выбрано как постоянное значение для повторения прогона. Для этой учебной модели оно не является паролем или ключом.

Откуда берётся уменьшение риска в 1000 раз?

При известном пароле код угадывается с вероятностью 0,001. Поэтому вероятность чужого успеха меняется с p до p × 0,001. Отношение этих вероятностей равно 1000.

Почему получилось 43 успеха, хотя ожидалось 50?

50 — среднее ожидаемое число для вероятности 0,00005 на миллион попыток. В одном конечном прогоне результат случаен. Для этого счётчика стандартное отклонение составляет около 7,1.

Почему дважды определяется знание пароля посторонним?

По заданию для каждого способа моделируется своя группа попыток. Каждый новый вызов распределения даёт отдельный исход для этой группы.

Как проверить, что программа работает?

Сначала запустить --test и получить четыре PASS. Затем запустить --csv, проверить девять сочетаний и сравнить доли с формулами модели. Повторный запуск готового файла должен воспроизвести приложенный CSV.

Какой вывод по безопасности и удобству?

Код снижает вероятность чужого входа. Удобство определяется надёжностью второго этапа. При заданных 10% или 20% отказов владелец теряет соответствующую долю успешных попыток.
