# Разбор кода курсовой КР104

[Открой `main.cpp`](main.cpp) и иди по нему сверху вниз. Программа сравнивает вход по паролю и вход по паролю с одноразовым кодом. Для каждого сочетания условий она считает успешные входы постороннего и владельца. При обычном запуске вводить ничего не нужно. Все параметры уже заданы в коде.

```powershell
.\bin\kr104.exe
.\bin\kr104.exe --test
.\bin\kr104.exe --csv my-results.csv
```

Первая команда печатает таблицу, вторая запускает четыре проверки правила входа, третья дополнительно записывает таблицу и счётчики в `my-results.csv`.

## 1 Библиотеки

| Подключение | Где используется |
| --- | --- |
| `<iostream>` | `std::cout` выводит таблицу, `std::cerr` печатает ошибки. |
| `<iomanip>` | `std::setw` выравнивает столбцы, а `std::setprecision` задаёт точность вывода. |
| `<fstream>` | `std::ofstream` записывает результаты в файл. |
| `<random>` | `std::mt19937` даёт последовательность псевдослучайных чисел, `std::uniform_int_distribution` выбирает число из нужного диапазона. |
| `<string>` | `std::string` позволяет сравнить аргумент запуска с `--test` или `--csv`. |

`std::` указывает, что имя взято из стандартной библиотеки C++. Например, `std::cout` — знакомый из лабораторных поток вывода.

## 2 Правило входа

Функция [`canLogIn`](main.cpp#L7) получает три значения типа `bool`. У `bool` два значения: `true` — да, `false` — нет.

| Параметр | Что означает |
| --- | --- |
| `password_known` | Пароль известен. |
| `needs_code` | Для входа требуется дополнительный код. |
| `code_correct` | Второй этап успешно пройден. |

1. `if (!password_known)` означает «если пароль неизвестен». `return false` сразу завершает функцию с отказом.
2. При известном пароле и `needs_code == true` функция возвращает `code_correct`. Правильный код даёт успех, неправильный — отказ.
3. В остальных случаях пароль уже известен, а второй этап выключен. Поэтому выполняется `return true`.

Например, `canLogIn(true, false, false)` возвращает `true`: пароль известен, код для этого способа входа не требуется. `canLogIn(false, true, true)` возвращает `false`: проверка пароля останавливает вход сразу.

## 3 Запуск и проверки

Выполнение начинается с [`main`](main.cpp#L28). `argc` считает аргументы вместе с именем программы, а `argv` хранит их по порядку. При запуске без параметров `argc` равен 1. Для команды `kr104.exe --csv my-results.csv` он равен 3, `argv[1]` содержит `--csv`, а `argv[2]` — путь к файлу.

В условии `argc == 2 && std::string(argv[1]) == "--test"` знак `&&` означает «и». Сначала проверяется число аргументов. Если оно другое, C++ пропускает правую часть и не обращается к отсутствующему `argv[1]`.

В режиме `--test` функция [`checkCase`](main.cpp#L17) для одной пары «пароль, код» вызывает `canLogIn` дважды, по одному разу на способ входа. Она сравнивает оба ответа с ожидаемыми и печатает `PASS` или `FAIL`. Например, `checkCase(true, false, true, false)` проверяет известный пароль и неправильный код. Ожидается успех по одному паролю и отказ при втором этапе.

| Пароль известен | Код верен | Только пароль | Пароль и код |
| --- | --- | --- | --- |
| Нет | Нет | Отказ | Отказ |
| Нет | Да | Отказ | Отказ |
| Да | Нет | Успех | Отказ |
| Да | Да | Успех | Успех |

Запись `условие ? A : B` выбирает `A` при верном условии, `B` при неверном. Так выбирается текст `PASS` / `FAIL` и код завершения режима проверки. После четырёх тестов этот режим завершает программу до запуска симуляции.

## 4 Параметры и случайные числа

В [`main.cpp`](main.cpp#L57) три вероятности компрометации хранятся в массиве `password_chances` — `1`, `5`, `10`. Три вероятности отказа владельца хранятся в `owner_failures` — `0`, `10`, `20`. Это проценты. `const` запрещает менять значения после объявления. Апострофы в записи `1'000'000` помогают читать число и не влияют на его значение.

`generator` создаётся с начальным числом `104005`. Пара `generator` и `random_number` работает так: вызов `random_number(generator)` возвращает целое от 1 до 1000, причём все 1000 значений равновероятны. С фиксированным начальным числом готовая программа повторяет тот же эксперимент при каждом запуске.

| Случайное событие | Как моделируется |
| --- | --- |
| Посторонний знает пароль | Число не больше `password_chance * 10`. Например, 5% — это числа от 1 до 50. |
| Посторонний угадывает код | Число равно 1. Один исход из тысячи даёт 0,1%. Если пароль неизвестен, код не проверяется. |
| Владелец проходит второй этап | Число больше `owner_failure * 10`. При отказе в 10% случаев числа 1–100 дают отказ, а 101–1000 — успех. |

## 5 Три цикла и четыре счётчика

Первая строка [`for`](main.cpp#L71) берёт по очереди `1`, `5`, `10` из `password_chances`. Второй цикл внутри неё для каждого из этих значений перебирает `0`, `10`, `20` из `owner_failures`. Получается девять пар. При переходе к новой паре все четыре счётчика снова равны нулю.

Третий цикл `for (int attempt = 0; attempt < attempts; ++attempt)` повторяет расчёт миллион раз для каждой пары. `attempt` начинается с 0, `++attempt` прибавляет единицу после каждого прохода, а условие `attempt < attempts` останавливает цикл при достижении миллиона. За один проход оцениваются четыре отдельные попытки.

| Счётчик | Когда прибавляется единица |
| --- | --- |
| `outsider_password` | Посторонний знает пароль для входа только по паролю. |
| `outsider_two_step` | В отдельной попытке посторонний знает пароль и угадывает код. |
| `owner_password` | Владелец входит по паролю. Это происходит каждый раз, потому что пароль ему известен. |
| `owner_two_step` | Владелец входит с кодом, если успешно проходит второй этап. |

Для двух попыток постороннего получаются отдельные случайные числа. Если в одной попытке он знал пароль, из этого нельзя сделать вывод о другой. Когда `canLogIn` возвращает `true`, `++` увеличивает соответствующий счётчик. За девять пар получается `9 × 1 000 000 × 4 = 36 000 000` попыток.

### Пример одного прохода

Возьмём утечку пароля 5% и отказ владельца 10%. Допустим, для входа постороннего по паролю выпало `30`. Это не больше `50`, поэтому первый счётчик увеличится. Для его отдельной попытки с кодом пусть выпадут `41` на проверке пароля и `278` на проверке кода. Пароль известен, но для правильного угадывания требовалась `1`, поэтому второй счётчик останется прежним. Владелец по паролю войдёт всегда. Если для его второго этапа выпало `87`, код считается неполученным, и четвёртый счётчик тоже останется прежним.

## 6 Как читается результат

После миллиона проходов каждый счётчик переводится в проценты по формуле `100.0 * число_успехов / attempts`. `100.0` задаёт вещественное вычисление, чтобы сохранялась дробная часть. `std::fixed` использует обычную десятичную запись, `std::setprecision(4)` оставляет четыре знака после точки, а `std::setw(10)` задаёт минимальную ширину следующего числа в таблице.

В проверенном прогоне для `5%` и `10%` посторонний вошёл `50 112` раз по паролю и `43` раза с кодом. Последнее даёт `100 × 43 / 1 000 000 = 0,0043%`. Владелец вошёл `1 000 000` раз по паролю и `900 396` раз с кодом, что составляет `100%` и `90,0396%`.

При `--csv` программа открывает файл по пути из `argv[2]`, записывает заголовок и по одной строке на сочетание параметров. Значения разделяются запятыми. После записи вызывается `csv.close()`, затем проверяется состояние файла. Код завершения `0` означает успех, `1` — ошибку проверки или работы с файлом, `2` — неверную команду запуска.

## Что сказать на защите

> Я сравниваю вход по одному паролю и вход с дополнительным кодом. Два внешних цикла перебирают девять сочетаний вероятностей. Внутренний цикл оценивает по миллиону попыток на каждого участника и способ входа. Случайное число от 1 до 1000 моделирует событие: для вероятности 5% подходят первые 50 чисел, а для угадывания кода подходит только 1. Функция `canLogIn` проверяет пароль и при необходимости код. Успехи считаются отдельно и переводятся в проценты.

- **Почему теоретически риск меньше в 1000 раз?** Для чужого входа с кодом нужно знать пароль и угадать код с вероятностью `0,001`. Если вероятность знать пароль равна `p`, то шанс входа меняется с `p` до `p × 0,001`.
- **Почему при 5% утечек получилось 43 входа с кодом, хотя ожидалось 50?** `50` — математическое ожидание, а `43` — один результат конечного случайного прогона.
- **Почему владелец получает около 90% успехов при 10% отказов?** Он знает пароль всегда. Код проходит с вероятностью `1 − 0,10 = 0,90`.
- **Почему нужно четыре счётчика?** Есть два участника, и для каждого измеряются результаты двух способов входа.
